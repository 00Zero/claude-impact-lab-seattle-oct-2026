# Lean Canvas — note-style workflow only

Working hypotheses unless explicitly supported by the de-identified customer journey.

## 1. Problem

Clinicians need notes in an established style; prompt customization requires technical translation; later changes depend on repeated support. Existing alternatives: manual writing, generic templates, cloud scribes, founder-assisted prompts.

## 2. Customer segments

Therapists using local note generation; initial adopters are existing Scribular users requesting customization. Buyer hypothesis: independent practitioners, later small practices. One customer is evidence of a concrete need, not market size.

## 3. Unique value proposition

“Your note style, created locally and improved with feedback you control.”

## 4. Solution

Upload documents -> internal refinement on one selected fictional transcript -> Template Control (generated draft or defaults) -> Main Meeting simulation with a different fictional transcript and real Ollama. My Note Style exposes active version/preferences, later updates, history, and rollback. Learning concerns explicit preferences and prompts, not automatic weight training.

## 5. Channels

Existing customers first; in-app invitation, short fictional-session demos, clinician referrals, and relevant communities. Acquisition effectiveness is unvalidated.

## 6. Revenue

Test inclusion in Scribular versus an ongoing customization tier. No pricing decision or new spend authorization. Existing purchase evidence does not establish willingness to pay separately for a coach.

## 7. Costs

Local runtime integration, compatibility, clinician review, evaluation fixtures, support, maintenance, and regression testing. Local inference shifts compute to the device; it does not eliminate costs.

## 8. Key metrics

Independent completion, editing time, founder support, fresh-case acceptance, factual failures, latency, update acceptance, and rollback. Primary outcome: less editing effort without worsening factual fidelity.

## 9. Potential unfair advantage

Founder experience translating preferences, existing customer relationships, and a growing clinician-reviewed local-runtime regression suite. These are potential advantages, not established defensibility.

## Riskiest assumptions

A clinician can independently create an acceptable style; a local refinement loop earns its latency; continued updates reduce recurring corrections without regressions.

## Latest scope/data refinement

No customer-style marketplace. Continuous improvement remains in scope. Capture intake friction, refinement cost, generated-vs-default selection, fresh-case acceptance, targeted feedback, approvals and restores. Detailed content stays local; optional product analytics use a content-free allowlist.
